# เช็กลิสต์วางระบบอัตโนมัติสำหรับ SME

ใช้รายการนี้ก่อนเริ่มระบบอัตโนมัติหนึ่งกระบวนการ ตั้งผู้รับผิดชอบและแนบหลักฐาน
การตัดสินใจในแต่ละข้อที่เกี่ยวข้อง หากยังตอบไม่ได้ ให้หยุดที่ขั้นนั้นและตกลง
ผู้อนุมัติหรือเจ้าของความเสี่ยงก่อนเปิดใช้

## 1. กำหนดขอบเขตและทางหยุด

- [ ] เขียนจุดเริ่มต้น ข้อมูลเข้า ขั้นตอน ผลลัพธ์ และจุดสิ้นสุดของกระบวนการ
- [ ] ระบุระบบและผู้รับผิดชอบทุกจุดที่ข้อมูลถูกอ่าน เปลี่ยน ส่ง หรืออนุมัติ
- [ ] ระบุกรณียกเว้นที่ต้องให้คนตรวจ และวิธีหยุดงานอัตโนมัติทันที
- [ ] กำหนดขอบเขตว่าอะไรทำได้ อะไรห้ามทำ และใครมีอำนาจเปลี่ยนขอบเขต
- [ ] บันทึกวิธีทำงานเดิมและเกณฑ์ตรวจรับที่วัดได้ก่อนเริ่มปรับระบบ
- [ ] ระบุเจ้าของกระบวนการ ผู้ดูแลระบบ ผู้อนุมัติ และผู้รับแจ้งเหตุ

## 2. ความเป็นส่วนตัวและข้อมูล

- [ ] ทำรายการชนิดข้อมูล แหล่งที่มา วัตถุประสงค์ ผู้เข้าถึง และปลายทาง
- [ ] ตัดข้อมูลที่ไม่จำเป็นออก และกำหนดฟิลด์ขั้นต่ำที่ระบบต้องใช้
- [ ] ตรวจว่ามีสิทธิและฐานการใช้ข้อมูลตามนโยบายองค์กรและข้อกำหนดที่เกี่ยวข้อง
- [ ] กำหนดการแจ้งผู้ใช้/ลูกค้าเมื่อจำเป็น และผู้รับผิดชอบอนุมัติข้อความแจ้ง
- [ ] จำกัดสิทธิ์ตามหน้าที่ แยกบัญชีระบบจากบัญชีบุคคล และทบทวนสิทธิเป็นระยะ
- [ ] เก็บรหัสผ่าน กุญแจ API และโทเคนในที่จัดเก็บความลับที่องค์กรอนุมัติ
- [ ] ปกปิดหรือตัดข้อมูลระบุตัวบุคคลและความลับออกจาก log, alert และตัวอย่างทดสอบ
- [ ] กำหนดระยะเวลาเก็บ วิธีลบ และผู้รับผิดชอบเมื่อต้องลบข้อมูล
- [ ] ตรวจเงื่อนไขการประมวลผล การเก็บรักษา และการส่งต่อข้อมูลของผู้ให้บริการที่ใช้
- [ ] ใช้ข้อมูลสังเคราะห์หรือข้อมูลที่ปกปิดแล้วในสภาพแวดล้อมทดสอบ

## 3. ความถูกต้อง การทำซ้ำ (idempotency) และความปลอดภัยของผลข้างเคียง

- [ ] กำหนด idempotency key ที่คงที่จากรหัสเหตุการณ์ต้นทางและชนิดงาน เพื่อใช้ตรวจและป้องกันการทำผลข้างเคียงซ้ำ
- [ ] กำหนดช่วงเวลาตรวจซ้ำและเก็บสถานะของงานที่รับ กำลังทำ สำเร็จ หรือผิดพลาด
- [ ] ทดสอบเหตุการณ์เดิมที่เข้าซ้ำพร้อมกัน แล้วตรวจว่าไม่เกิดผลข้างเคียงซ้ำ
- [ ] ให้การเรียกซ้ำด้วยรหัสเดิมอ่านผลเดิมหรือเข้าสู่การตรวจซ้ำตามกติกาที่กำหนด
- [ ] ระบุลำดับเหตุการณ์ที่ยอมรับได้ และวิธีจัดการเหตุการณ์มาช้า/ผิดลำดับ
- [ ] ไม่สมมติว่าการส่งข้อมูลครั้งเดียวเท่ากับการทำงานครั้งเดียว ให้บันทึกข้อจำกัดของแต่ละระบบ
- [ ] ทดสอบกรณีทำงานสำเร็จบางส่วน และระบุวิธีตรวจหาหรือแก้ข้อมูลที่ไม่ตรงกัน

## 4. จุดอนุมัติและการควบคุมโดยคน

- [ ] กำหนดให้คนอนุมัติก่อนส่งข้อความถึงลูกค้า เปลี่ยนข้อมูลสำคัญ จ่ายเงิน หรือลบข้อมูล
- [ ] แสดงข้อมูลก่อน/หลัง รายการที่จะเกิดผล และเหตุผลให้ผู้อนุมัติเห็นก่อนตัดสินใจ
- [ ] บันทึกผู้อนุมัติ เวลา ผลอนุมัติ และหมายเหตุ โดยไม่เก็บข้อมูลส่วนบุคคลเกินจำเป็น
- [ ] ระบุผู้แทนเมื่อผู้อนุมัติไม่พร้อม และห้ามระบบอนุมัติตนเอง
- [ ] กำหนดวันหมดอายุของคำขออนุมัติ และวิธีจัดการเมื่อข้อมูลเปลี่ยนหลังอนุมัติ
- [ ] ทดสอบปฏิเสธ ยกเลิก หมดเวลา และส่งกลับแก้ไข

## 5. Retry, timeout และคิวงานผิดพลาด

- [ ] แยกความผิดพลาดชั่วคราวออกจากข้อมูลผิดหรือสิทธิไม่พอที่ต้องแก้ก่อนลองใหม่
- [ ] ตั้ง timeout ต่อการเรียกและจำนวนครั้งสูงสุด พร้อมช่วงพักแบบเพิ่มขึ้นและสุ่มหน่วง
- [ ] เคารพคำแนะนำเวลารอจากระบบปลายทางเมื่อมี และจำกัดเวลารวมของงาน
- [ ] ตรวจการทำงานซ้ำให้ปลอดภัยก่อนเปิด retry สำหรับขั้นตอนที่มีผลข้างเคียง
- [ ] ส่งงานที่ล้มเหลวถาวรไปคิวตรวจสอบ พร้อมเหตุผล รหัสอ้างอิง และวิธีกู้คืน
- [ ] กำหนดว่าใครนำงานกลับเข้าคิวได้ และตรวจการอนุมัติก่อน replay งานสำคัญ
- [ ] ทดสอบเมื่อปลายทางช้า ปฏิเสธคำขอ จำกัดอัตรา หรือกลับมาใช้ได้หลังหยุดชั่วคราว

## 6. การติดตามและแจ้งเหตุ (monitoring)

- [ ] บันทึกจำนวนงานที่รับ สำเร็จ ผิดพลาด ลองซ้ำ ซ้ำซ้อน และรออนุมัติ
- [ ] วัดเวลารอและเวลาทำงาน รวมถึงจำนวนงานค้างและอายุของงานที่เก่าที่สุด
- [ ] ใช้รหัสติดตามเดียวกันข้ามขั้นตอน โดยไม่ใส่ข้อมูลลับหรือเนื้อหาลูกค้าในรหัส
- [ ] ตั้งการแจ้งเตือนที่ระบุอาการ ระดับความเร่งด่วน เจ้าของ และขั้นตอนแรกที่ต้องทำ
- [ ] ทดสอบว่าการแจ้งเตือนถึงผู้รับจริง และมีผู้รับช่วงเมื่อไม่มีคนตอบ
- [ ] จัดทำคู่มือดูสถานะ หยุดงาน ตรวจ log แบบปกปิดข้อมูล และยกระดับเหตุ

## 7. ทดสอบและเปิดใช้งาน

- [ ] ทดสอบกรณีปกติ ข้อมูลไม่ครบ ข้อมูลผิด สิทธิไม่พอ และระบบปลายทางหยุดทำงาน
- [ ] ทดสอบเหตุการณ์ซ้ำ มาพร้อมกัน มาผิดลำดับ timeout และความล้มเหลวบางขั้น
- [ ] ตรวจทั้งผลที่คาดหวังและผลข้างเคียงในระบบต้นทาง/ปลายทาง
- [ ] ให้เจ้าของกระบวนการตรวจตัวอย่างผลจริงด้วยข้อมูลสังเคราะห์ก่อนอนุมัติเปิดใช้
- [ ] เริ่มด้วยโหมดจำลองหรือขอบเขตเล็ก พร้อมกำหนดผู้เฝ้าดูและเกณฑ์หยุด
- [ ] บันทึกเวอร์ชัน การตั้งค่า วันเปิดใช้ และผู้อนุมัติทุกครั้ง
- [ ] เปิดใช้ต่อเมื่อมีผู้รับผิดชอบ ช่องทางแจ้งเหตุ และแผนย้อนกลับที่ทดลองแล้ว

## 8. ย้อนกลับ (rollback) และกู้คืน

- [ ] ระบุสวิตช์หยุดอัตโนมัติ ผู้มีสิทธิใช้ และวิธีปิดที่ไม่ทำข้อมูลที่รับแล้วสูญหาย
- [ ] เก็บเวอร์ชันก่อนหน้าและขั้นตอนคืนค่า พร้อมกำหนดผู้อนุมัติการย้อนกลับ
- [ ] ระบุวิธีพัก ตรวจ และจัดการงานที่ค้างระหว่างหยุดหรือย้อนเวอร์ชัน
- [ ] วางขั้นตอนกระทบยอดข้อมูลต้นทาง/ปลายทางหลังการหยุดหรือกู้คืน
- [ ] กำหนดการชดเชยผลที่ย้อนคืนตรง ๆ ไม่ได้ และให้คนอนุมัติก่อนดำเนินการ
- [ ] ซ้อมสถานการณ์หยุดระบบ กู้ข้อมูล เปิดคิวกลับ และแจ้งผู้เกี่ยวข้อง
- [ ] บันทึกสิ่งที่เกิดขึ้น การตัดสินใจ ผู้รับผิดชอบ และรายการติดตามหลังเหตุ

## ก่อนส่งมอบ

- [ ] มีเจ้าของระบบและผู้รับช่วงดูแลเมื่อผู้พัฒนาไม่อยู่
- [ ] คู่มือการทำงานและข้อจำกัดตรงกับระบบที่เปิดใช้จริง
- [ ] ผู้อนุมัติรับทราบข้อมูลที่เก็บ สิทธิ์ จุดตรวจโดยคน และวิธีหยุดระบบ
- [ ] มีวันทบทวนสิทธิ์ การเก็บข้อมูล กฎ retry และแผนกู้คืน
